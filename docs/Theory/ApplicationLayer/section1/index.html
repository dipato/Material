Section 1 - Message Queuing Telemetry Transport (MQTT)

The installation is the same whether it's done on a desktop computer or on the Raspberry Pi. To get things started, we’ll run the test on the computer.

Installation​

  1. Update the packages: Before getting started, it's a good idea to update the package list:

    sudo apt-get update

  2. Check that the packages related to Mosquitto are available: Make sure that the available package list includes those related to Mosquitto:

    apt-cache search mosquitto

  1. Install the MQTT broker: To install the MQTT broker, use the following command:

Verifying the broker's operation​

After installing the broker, it's a good idea to verify that it is running. This can be done in several ways:

  1. Using the netstat command: For more detailed output, use the-tanlp option, which stands for: tcp, all, numeric, listening, program.

    sudo netstat -tanlp | grep 1883

  1. Using the ps command: The ps command is used with the -ef option, piped to the grep command to filter the search:

Additional Broker Configuration​

Starting from version 1.7, Mosquitto does not allow anonymous communication.

To re-enable this option, you must create a configuration file named standard.conf inside the /etc/mosquitto/conf.d/ directory with the following content:

allow_anonymous true
listener 1883
protocol mqtt

The procedure is described below:

  1. Create the file /etc/mosquitto/conf.d/standard.conf using vi or your favorite editor as superuser:

    sudo vi /etc/mosquitto/conf.d/standard.conf

    The command executed on the rPi is shown below:

  1. Edit the newly created file by adding the following content:

    allow_anonymous true
    listener 1883
    protocol mqtt

    When editing the configuration file using vi, we have:

  1. Save the changes: in vi, press the ESC key, then type :wq and finally press Enter:

  1. Verify that the file was created correctly using the cat command:

    cat /etc/mosquitto/conf.d/standard.conf

    If everything is correct, something like the following should appear:

  1. Restart the broker:

    sudo systemctl mosquitto start

Verify the installation​

Finally, the last step is to verify that the broker is working properly by checking whether a client can subscribe to a topic and whether another client can publish a command to it. In this case, the test involved the rPi (where the broker is running) and an external device (PC) from which a message is published. The test topic is test/topic and the message sent is Hello, MQTT!. The characteristics of the connected devices are shown below:

DeviceDescriptionIP
1Raspberry Pi192.168.1.31
2PC192.168.1.4

Raspberry Pi​

  1. Open a terminal and subscribe a client to the test/topic topic:

    mosquitto_sub -t test/topic

    The result is shown below:

  1. Open a different terminal and publish the message Hello, MQTT! to the test/topic topic:

    mosquitto_pub -t test/topic -m "Hello, MQTT!"

    The following figure shows the result:

If everything is correct, the recently sent message should appear in the terminal of the subscribed client (step 1):

PC​

It is important to clarify that the PC must have at least the Mosquitto clients installed. Before starting, it is necessary to verify that there is communication between the PC (192.168.1.4) and the rPi (192.168.1.31):

ping 192.168.1.31

If everything is correct, the output will be as follows:

Then, from a terminal on the PC, publish any message (in our case we use the same one) to the test/topic topic. Keep in mind that the broker is running on the rPi, so its IP address (192.168.1.31) must be included in the command:

mosquitto_pub -h 192.168.1.31 -t test/topic -m "Hello, MQTT!"
